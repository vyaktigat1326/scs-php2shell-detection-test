# scs-php2shell-detection-test

Detection fixture for Aqua SCS: does repository or artifact scanning find
PHP2Shell (CVE-2026-109618, CVE-2026-109619) in a PHP runtime?

This repository contains **no exploit code**. The PHP entry point only prints
`PHP_VERSION`, and nothing here runs the interpreter.

## Affected versions

| PHP branch | Vulnerable | First fixed |
|---|---|---|
| 8.2 | < 8.2.35 | 8.2.35 |
| 8.3 | < 8.3.36 | 8.3.36 |
| 8.4 | < 8.4.27 | 8.4.27 |
| 8.5 | < 8.5.12 | 8.5.12 |
| ≤ 8.1 | all (EOL) | none |

## Test cases

Each case directory is a self-contained scan target.

| Case | PHP runtime | Expected findings |
|---|---|---|
| `cases/vulnerable-php-8.4.26/` | 8.4.26 | CVE-2026-109618, CVE-2026-109619 |
| `cases/patched-php-8.4.27/` | 8.4.27 | neither CVE |

Each case contains:

- `composer.json` / `composer.lock`: `require.php` and `config.platform.php` pinned to the
  case's exact version, plus one harmless dependency (`psr/log` 3.0.2) so the
  Composer parser has something to report. The lock file was generated by real
  Composer 2.
- `public/index.php`: harmless entry point.
- `runtime/usr/local/bin/php`, `runtime/usr/local/sbin/php-fpm`: **genuine** PHP
  binaries (linux/arm64) taken from the official images, pinned by digest:
  - 8.4.26: `php@sha256:f5431b57bda75455d5271967cc6b67df8f0d0b943832756e0c78eccdc98767dd`
  - 8.4.27: `php@sha256:e2d8e787dc775bdbd9d7e0c5e8f2f9ddb41ce5977c8bbaf99a2ba2e7d90fd8ae`
- `.php-version`: the expected interpreter version.
- `SHA256SUMS`: checksums of the binaries.

A version requirement in `composer.json` declares what the app *needs*. It does
not prove which interpreter is installed. Only the binaries prove that.

## Reproduce and verify

```bash
./scripts/extract-runtime.sh   # re-extract the binaries (needs Docker; pulls by digest)
./scripts/verify-runtime.sh    # check SHA-256 sums and the version compiled into each binary
```

`verify-runtime.sh` reads the `X-Powered-By: PHP/<version>` string that the PHP
build compiles into every SAPI binary. It never executes the binaries.

The versions were also confirmed by running `php -v` / `php-fpm -v` inside the
source images. The output was `PHP 8.4.26 (fpm-fcgi) (built: Oct 21 2026 00:33:09)`
and `PHP 8.4.27 (fpm-fcgi) (built: Oct 21 2026 15:58:17)`.
